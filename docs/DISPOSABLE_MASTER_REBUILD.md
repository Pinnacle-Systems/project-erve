# Seed-free disposable master rebuild

`pnpm --filter @erve/api master-data:rebuild-disposable --config <absolute-json> --plan` checks a sealed normalization manifest, parses the selected files, verifies the live disposable database identity and inspects ownership/storage paths. It creates no database objects, owner markers, reports, media or directories. A fresh target has no domain tables yet, so live dependency matching occurs after the system bootstraps during execution.

Use `--execute --confirm-write` to run committed migrations, roles, an explicitly supplied admin, the financial-year window, canonical quality/process-flow definitions, DRAFT GST definitions, reference masters and business imports. This calls the same Factory/Distributor/Store and Style services as the application. It never invokes the generic development seed, drops a database, truncates tables, imports historical transactions or activates financial configuration.

The operator must provision a **new empty local PostgreSQL database** named `erve_rebuild_<purpose>_test`, independently verify its endpoint, and supply that exact name and server address. Only loopback connection hosts are accepted; production mode is refused. `REBUILD_DEVELOPMENT_DATABASE_URL`, when supplied, must identify another database, including across loopback aliases/default ports. Existing nonempty targets require a committed database ownership comment from this runner. A database advisory lock prevents two rebuilds from owning the same target simultaneously.

Configuration fields:

| Field                                   | Meaning                                                                                                       |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `disposableId`                          | Newly generated 32-character lowercase hexadecimal ownership ID                                               |
| `databaseName`, `expectedServerAddress` | Independently verified live target identity                                                                   |
| `sourceRoot`                            | Absolute external canonical normalization directory                                                           |
| `manifestFile`, `manifestSha256`        | Relative manifest path and reviewed SHA-256                                                                   |
| `files`                                 | Relative manifest-declared `seasons`, `sizes`, `factories`, `distributors`, `retailStores` and `styles` paths |
| `styleWorksheet`                        | Explicit Style worksheet name                                                                                 |
| `businessWorksheets`                    | Explicit worksheet names for business XLSX files; omitted for CSV                                             |
| `adminEmail`, `adminName`               | Intended disposable system account; no demo credentials                                                       |
| `reportRoot`, `mediaRoot`               | Absolute external, separate directories ending in `rebuild-<disposableId>` and `media-<disposableId>`         |
| `syntheticCorrections`                  | Explicit engineering-only `{field, reason, sourceKey, value}` records; never commercial approvals             |

Set `DATABASE_URL` to that target, `FILE_STORAGE_DIR` to the exact isolated media root, and `ADMIN_PASSWORD_FILE` to a protected external password file. The password is read lazily by the existing admin bootstrap and never printed. Generated data stays outside the repository and outside the replaceable database. Links/junctions, overlapping roots, unowned directory contents, mismatched manifest/file hashes and reused target identities fail closed before writes.

Ownership binds the database, nonce, report path and media path. Existing output/media descendants, including marker files, must contain no links or junctions. A competing filesystem owner is rechecked when exclusive marker creation loses a race; mismatched ownership stops before database stamping or imports. The database comment is committed independently of the long-running advisory-lock transaction: a process interruption cannot roll it back after imported masters committed. Each stage checkpoints a new external run JSON. On interruption, preserve the target/media/report directories and retry the same reviewed configuration; exact masters skip without additional codes, barcodes or images. Changed commercial values are review exceptions rather than overwrites. Controlled corrections require newly sealed input checksums and a new preview; keep their provenance separate from original evidence.

Source Seasons without a Financial Year stay unresolved. Sizes and Seasons use existing CRUD services with exact create-only matching. HSN codes are copied from the selected sealed Style worksheet, with no invented classifications. Distributor modes are never defaulted; Stores require an unambiguous active parent. Seller registrations, statutory dates, customer price lists and commercial activation still require reviewed values through their existing authorized workflows.

The shared Style planner now compares existing names, MRP, Season/LMIX, supplied HSN, Sizes/barcodes, factory mappings/rates and expected images before reporting a skip. Changed data requires review, and a planned skip is checked again at execution. Blank optional barcodes preserve existing values rather than regenerating them. Exact retries and verified interrupted-image recovery remain supported.

Reports include target identity, schema revision, bootstrap outcomes, per-row import outcomes, source hashes, synthetic-correction disclosures, counts and a semantic business snapshot. Snapshot comparison ignores generated IDs/timestamps but includes master codes/values, Style–Season/FY links, barcodes, factory rates/statuses and verified stored-image checksums. CLI exit codes are `0` for completion without exceptions, `2` for completed source/business exceptions, and `1` for a refused/interrupted run or unexpected import failures. These categories do not authorize a commercial cutover.

The packaged artifact also contains `disposable-rebuild.js`, `master-source-normalize.js` and `style-bulk-import.js`. The rebuild entrypoint supports the same arguments under plain Node without a TypeScript loader; it locates the committed Prisma configuration and executes `migrate deploy` locally.

Actual-source engineering validation used a newly provisioned, independently verified local Podman target. The no-write plan saw zero schema objects and created no output/media directories. Execution loaded four Factories, two Seasons, 12 Sizes, 92 Styles, 552 barcode rows and 91 images. Unclassified Distributors, unresolved Store parents and AW26 Season references remained exceptions. Retrying after a reporting interruption and running the plain-Node bundle skipped existing masters and verified the same stored media. PR8 supplies second-target equivalence, controlled correction, explicit fault injection, authenticated browser and operational acceptance.

Commercial replacement remains a separate operator action: verify a current database backup and retained media recovery, seal reviewed source/correction files, provision the replacement target, replay and reconcile, obtain cutover/deployment authorization, then switch the application. The locally retained pre-H3A historical backup is not proof of current production recovery; unavailable retained media and current-backup evidence must be resolved independently. This runner does not contact production or perform that replacement.
